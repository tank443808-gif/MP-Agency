# 다먹음 개발 문서

개발 내용과 자료(기획서, 화면 설계, 요구사항 등)를 이 폴더에 모읍니다.

## 실행 방법

| 무엇을 볼지 | 명령 |
|---|---|
| 실제 앱 (로그인 → 역할별 화면) | `flutter run -d chrome` |
| 구매자 화면만 (로그인 없이) | `flutter run -d chrome -t lib/dev/home_preview.dart` |
| 판매자 화면만 (로그인 없이, "신구 베이커리" 사장님) | `flutter run -d chrome -t lib/dev/seller_preview.dart` |
| 모든 화면 넘침(노란 줄무늬) 검사 | `flutter test test/overflow_test.dart` |
| 규칙 검사 (환불·노쇼·알림·가격 필터 등) | `flutter test test/logic_test.dart` |

> **실제 앱(`main.dart`)은 Firestore에 저장**해요. 미리보기(`lib/dev`)와 테스트는 앱 메모리에만 저장해요.
> 회원가입 때 매장명을 "신구 베이커리"로 하면 예시 매장을 맡아요. 다른 이름이면 새 매장이 만들어져요.

## Firestore 구조

| 컬렉션 | 내용 (데이터 테이블 기술서) | 읽기 / 쓰기 |
|---|---|---|
| `users` | ① 회원 + 알림 설정(mutedNotificationGroups) | 본인만 |
| `stores` | ② 매장 | 로그인하면 보기 / 주인만 수정 |
| `products` | ③ 상품 (사진은 작게 줄여 문서 안에 저장) | 로그인하면 보기 / 매장 주인 등록·수정, 손님은 예약 시 재고만 |
| `reservations` | ④⑤ 예약 + 예약 상품 정보(한 문서) | 예약한 손님과 매장 주인 |
| `notifications` | ⑦ 알림 | 받는 사람만 보기 |
| `favorites` | 찜 (문서 ID = 회원ID_매장ID) | 본인만 쓰기 |
| `user_behavior_events` | ⑨ 행동 기록 (AI 추천) | 본인만 |

- ⑥ user_stats(다먹음 지수·등급)는 기획서 수정사항대로 저장하지 않고 예약 기록으로 계산해요.
- ⑧ product_categories는 앱 안의 고정 목록(베이커리·간편식·카페·식사)으로 대신해요.
- 예약은 **트랜잭션**으로 재고 확인과 차감을 한 번에 해서, 동시에 예약해도 재고를 넘지 않아요.
- 처음 로그인할 때 예시 매장 4곳이 없으면 만들고, 주인 없는 예시 매장에 판매 중인 상품이 없으면 새로 채워요.
- 보안 규칙: `firestore.rules` → 배포는 `firebase deploy --only firestore:rules --project mp-agency`

## 기능명세서 대응표

| 기능 ID | 어디서 | 비고 |
|---|---|---|
| AUTH-001, 004 | 로그인·회원가입 | 탈퇴한 계정(status=WITHDRAWN)은 로그인 불가 |
| HOME-001~003 | 홈 | 상품 카드: 사진(없으면 그림)·가격·할인율·남은 시간 |
| AI-001~005 | 홈 "○○님을 위한 추천" | 조회·검색·카테고리·추천 클릭·예약·수령 기록 반영 |
| SRCH-001~003 | 홈 검색·카테고리·**가격 범위** | 가격 칩 → 범위 슬라이더 |
| SRCH-005 | 홈 위치 ▾, 내 주변 | 현재 위치(GPS) 또는 **지역 선택** |
| PROD-001 | 상품 상세 | 픽업 시간(시작~종료) 표시 |
| SELL-003, 004 | 판매자 상품 등록·관리 | **사진**, 픽업 시작/종료, 수정, 판매 종료 |
| RSV-001, 002 | 상품 상세 → 예약 | 재고 초과 예약 막음 |
| RSV-005 | 예약 상세(손님), 예약 관리(사장님) | 사유별 환불: 아래 "환불 규칙" |
| MRSV-001, 004 | 예약 내역, 예약 관리 | 픽업 번호로 수령 확인, 픽업 시작 전엔 불가 |
| ECO-001~006 | 수령 완료, 나의 다먹음 | 지수·등급은 기록으로 계산 |
| DASH-001, 005 | 판매자 대시보드 | **기간 선택**(오늘/이번 주/이번 달/전체) |
| NOTI-001 | 알림 | 예약 완료·**픽업 30분 전**·노쇼·취소/환불·**찜 매장 새 상품 추천** |
| MY-001 | 나의 다먹음 → 프로필·알림 설정 / 내 가게 → 계정·알림 설정 | 닉네임 수정, 알림 켜기/끄기, 회원 탈퇴 |

## 환불 규칙 (RSV-005)

| 사유 | 환불 |
|---|---|
| 판매자 사정 (사장님이 취소) | 전액 환불 |
| 시스템 오류 | 전액 환불 |
| 상품 하자·정보 불일치 (손님이 사유 선택) | 전액 환불 |
| 단순 변심 (손님이 사유 선택) | 환불 불가 |
| 픽업 시간 지남 (노쇼, 자동 만료) | 환불 불가 |

## 계산 규칙

- **다먹음 지수 (0~100)** = 수령 횟수(최대 40) + 절약 금액(최대 25) + 폐기 방지 개수(최대 20) + 제시간 수령률(최대 15)
  - 기준: 수령 10회, 절약 5만 원, 구한 음식 20개면 각 항목 만점
- **등급**: 🌱 새싹(0~) → 🍀 알뜰러(25~) → 🌳 다먹러(50~) → 🏆 다먹음 마스터(80~)
- **폐기 감소율** = 판매 ÷ (판매 + 폐기). 판매가 끝난 뒤 남은 재고와 노쇼는 폐기로 계산
- **맞춤 추천 점수** = 선호 카테고리 35% + 평소 가격대 20% + 할인율 20% + 마감 임박 15% + 거리 10%
  - 조회·검색·카테고리 선택·추천 클릭·예약·수령 기록으로 취향을 계산 (예약·수령에 더 큰 가중치)
- **예약 상태**: 예약됨 → 수령완료 / 취소됨 / 기한만료(픽업 마감이 지나면 자동)

## 새 기능 추가 규칙

`lib/features/<기능이름>/` 폴더를 만들고 그 안에 아래처럼 나눕니다.

- `screens/` 화면 (`xxx_screen.dart`)
- `widgets/` 그 기능에서만 쓰는 작은 위젯
- `models/` 데이터 구조
- `services/` 데이터 처리 (지금은 메모리, 나중에 Firestore로 교체)

여러 기능이 같이 쓰는 위젯이나 유틸리티는 `lib/core/`에 둡니다.

## 디자인 규칙

- 색: 오렌지(주색) · 연두(친환경/성공) · 크림(배경). `AppColors` 사용
- 글꼴: 제목·가격·버튼은 `AppFonts.display()` (주아), 본문은 기본 글꼴 (고운돋움)
- 그림: 상품 그림은 이모지 + 파스텔 배경 (실제 사진이 생기면 `imageUrl` 우선)
- 아이콘: 카테고리 같은 메뉴 아이콘은 연한 살구색 원 + 오렌지 선 아이콘
- 선택 칩: Material 칩 대신 `PillChip` 사용 (웹에서 글자 잘림 방지)
- 말투: 무겁지 않고 재미있게 ("이거 버리기 아까운데… 다먹음?")
